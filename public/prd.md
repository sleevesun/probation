## 一、需求背景

### 1.1 用户是谁

- 员工：处于试用期，需要设定试用期目标、查看过程反馈、填写试用期评价并查看最终结果。
- 直属上级：负责确认/退回员工试用期目标、记录阶段性反馈、完成正式试用期评价和转正建议。
- HRBP：负责跟进试用期过程、在关键时间点开启评价，并在上级评价通过后发起转正审批。
- 审批人：在转正审批中查看试用期材料并完成审批。
- HR 管理者 / 业务负责人：需要通过系统留痕和流程推进，降低试用期管理风险。

### 1.2 用户问题是什么

- 员工入职后缺少统一的试用期目标沉淀，后续自评和上级评价缺少明确依据。
- 试用期过程中的问题反馈、沟通结论和整改要求主要在线下发生，系统内缺少阶段性记录。
- 上级和 HRBP 在 4.5 个月、5.5 个月等关键节点需要人工跟进，流程容易延迟。
- 转正审批材料分散，审批人无法在一个审批单中完整查看目标、自评、上级评价和审批记录。
- 当前后续调整仅以现代风格 Demo 为准；PS 风格暂不纳入本次调整和验收范围。

### 1.3 目标是什么

- 建立员工试用期目标制定、确认、调整和锁定机制，使正式评估有目标依据。
- 在正式转正评估发起前，支持直属上级随时填写阶段性反馈，并允许员工侧查看。
- 在 4.5 个月节点推动 HRBP 开启正式评估，员工逐目标自评，直属上级完成评价和转正建议。
- HRBP 基于目标、自评和上级评价发起转正审批，审批人可查看完整材料并审批。
- 明确本期不做的能力，包括附件上传、员工对阶段性反馈进行确认或申诉、HRBP 独立转正评价节点和新的审批引擎。

## 二、产品概述

### 2.1 业务流程图

![试用期转正业务流程图](图示/试用期转正业务流程图.svg)

```text
员工制定目标
-> 直属上级确认目标 / 退回修改
-> 直属上级可填写阶段性反馈
-> HRBP 在 4.5 个月节点开启试用期评价
-> 员工逐目标自评 + 总体评价
-> 直属上级评价 + 转正建议
-> HRBP 预览并发起转正审批流程
-> 审批人审批
-> 员工身份由试用员工变更为正式员工
-> 系统自动发布转正结果
-> 员工查看结果
```

### 2.3 状态流转

![试用期转正状态流转图](图示/试用期转正状态流转图.svg)

| 状态码 | 状态名称 | 当前处理人 | 进入条件 | 可操作动作 | 下一状态 |
| --- | --- | --- | --- | --- | --- |
| 01 | 待设定目标 | 员工 | 员工入职后具备权限并生成记录，或目标被退回；入职 1 周后推送目标设定待办 | 保存草稿、提交目标 | 02 |
| 02 | 目标待确认 | 直属上级 | 员工提交目标 | 确认目标、退回修改 | 03 / 01 |
| 03 | 目标已确认 | 无固定处理人 | 上级确认目标 | 上级可在评估开启前退回调整；直属上级可填写阶段性反馈；入职满 4.5 个月后 HRBP 可直接开启评价或终止转正 | 01 / 05 / 99 |
| 05 | 待员工自评 | 员工 | HRBP 开启评价 | 提交逐目标自评和总体评价 | 06 |
| 06 | 待上级评价 | 直属上级 | 员工提交自评 | 提交评价；HRBP 可终止转正 | 07 / 99 |
| 07 | 上级已评价 | HRBP | 上级评价完成 | 发起转正、终止转正 | 08 / 99 |
| 08 | 审批中 | 审批人 | HRBP 发起转正审批流程 | 通过、驳回 | 09 / 07 |
| 09 | 待身份变更 | 系统 | 审批通过，但员工类型尚未由试用员工变更为正式员工 | 监听员工身份变更 | 10 |
| 10 | 结果已发布 | 无 | 员工身份由试用员工变更为正式员工，系统自动发布结果 | 员工查看结果和上级评价结果 | 结束 |
| 99 | 终止转正 | HRBP / 系统 | HRBP 判断不进入后续流程，或上级评价不通过 | 查看记录，跳转相关人事流程 | 结束 |
| 11 | 未转正离职 | 无 | 员工在完成试用期转正流程前已离职 | 查看记录 | 结束 |

状态规则：

- 阶段性反馈不是必经节点，不改变主流程状态。
- 仅直属上级可在正式评估发起前新增阶段性反馈；HRBP 不可新增阶段性反馈。
- HRBP 在正式评估开启前的所有状态均可执行“终止转正”，包括待设定目标、目标待确认、目标已确认。
- HRBP 开启正式评估后，目标进入只读锁定状态。
- HRBP 在“待员工自评”和“待上级评价”两个阶段可执行“终止转正”，执行后进入“终止转正”并归入“已结束”。
- 员工提交自评后，只进入直属上级评价，不产生 HRBP 正式转正评价节点。
- 上级试用期评价选择“不通过”时，记录直接进入“终止转正”，不再进入 HRBP 发起转正审批流程。
- 审批退回默认回到“上级已评价”，由 HRBP 判断是否重新发起或退回前序评价；如审批系统已有规则，以审批系统配置为准。
- 审批通过后不再生成 HRBP 发布结果待办；员工身份由试用员工变更为正式员工时，系统自动发布转正结果。
- 结果自动发布后，员工默认可以查看上级评价结果，但默认不可查看审批记录。
- 员工在完成试用期转正流程前离职时，系统自动作废所有未完成表单，记录进入“已结束”，状态显示“未转正离职”。

## 三、功能性需求

### 3.1 [1][2][3] 员工端 - 我的试用期

#### 1. 基础逻辑

- 员工进入系统后查看本人试用期相关信息。
- 员工端只展示本人可理解和可操作的信息，不展示 HRBP 内部待办、上级评价详情、审批中后台流转细节。
- 员工当前状态模块命名为“当前进展”，用于承载可处理待办和不可处理的进展信息。
- Demo 中的员工切换组件放在侧边栏区域，不放在页面主体内容区。
- 现代风格 Demo 需要展示员工切换组件，位置为左侧菜单栏；PS 风格本次不纳入调整和验收。

#### 2. 页面详细说明

页面构成：

| 区域 | 说明 |
| --- | --- |
| 员工切换 | Demo 辅助组件，放在侧边栏，用于切换演示员工 |
| 页面标题 | 展示“我的试用期”和入职天数 |
| 当前状态 | 展示在页面标题下方 |
| 员工信息 | 展示员工基础信息，位于当前进展上方 |
| 当前进展 | 展示员工当前所处阶段、当前状态和下一步动作 |
| 试用期目标 | 展示员工已填写目标；未填写时展示目标制定入口 |
| 阶段性反馈记录 | 展示直属上级提交的阶段性反馈 |
| 试用期评价 | 正式评估开启后展示员工评价入口或已提交内容 |
| 结果信息 | 身份变更自动发布结果后展示最终通过/不通过结果和上级评价结果 |

展示逻辑：

- 员工首页入职天数展示为“已入职 XXX 天”，不展示“共 180 天”。
- 当前状态展示在“我的试用期”标题下方，不放在页面右上角。
- 员工信息和当前进展采用上下结构，员工信息在上，当前进展在下。
- 员工视角步骤建议展示为：`提交目标 -> 上级确认 -> 试用期评价 -> 试用期评估中 -> 完成`。
- 待设定目标状态下，当前进展说明文案为：`请与上级沟通后完成试用期目标设定，并提交上级确认。`
- 上级确认目标后，到员工需要自评前，员工阶段展示为“上级确认”，状态展示为“【进行中】目标已确认”。
- 员工不展示“待开启试用期评价”状态。
- 员工提交自评后，员工端统一展示为“试用期评估中”，不拆分展示“待上级评价”“上级已评价”“审批中”等后台状态。
- 已确认目标及后续阶段的演示员工，需要预置直属上级阶段性反馈数据，避免阶段性反馈记录长期为空。

#### 3. 功能交互

- 当前存在待办时，展示对应主按钮，如“填写目标”“填写试用期评价”。
- 当前无员工可操作事项时，仅展示当前进展，不展示后台处理按钮。
- 阶段性反馈记录仅可查看，不提供反馈、确认、编辑和删除动作。

### 3.2 [5][6] 员工端 - 目标制定

#### 1. 基础逻辑

- 员工入职后进入“待设定目标”状态。
- 员工最多填写 5 条试用期目标。
- 目标提交后进入直属上级确认。
- HRBP 开启正式评估后，目标锁定为只读。

#### 2. 字段说明

| 字段 | 字段说明 | 是否必填 | 规则 |
| --- | --- | --- | --- |
| 序号 | 目标行序号 | 否 | 系统按目标行自动生成，从 1 开始展示 |
| 目标内容 | 试用期内需要完成的事项 | 是 | 开放文本；页面列名需展示必填标识 |
| 预期结果 | 后续评价时参考的结果或标准 | 是 | 开放文本；页面列名需展示必填标识 |
| 权重 | 目标重要性辅助信息 | 否 | 可为空；如填写权重，各目标权重合计需为 100% |
| 备注 | 资源、协作、阶段说明等补充信息 | 否 | 开放文本 |

#### 3. 功能交互

- 员工可新增、编辑、删除目标。
- 员工可保存草稿。
- 员工点击“提交”后，系统校验必填字段和权重规则。
- 提交成功后进入“目标待确认”，直属上级生成目标确认待办。
- 目标被退回后，员工可查看退回意见并重新编辑提交。
- 员工目标列表第一列展示“序号”，不再展示“目标维度”下拉或目标维度信息。
- 员工自评和各类详情/预览中，目标字段统一展示“预期结果”，不再展示“衡量方式/预期结果”。
- Demo 员工切换列表中移除“赵雪梅”演示员工。

#### 4. 校验规则

| 场景 | 处理规则 |
| --- | --- |
| 所有目标权重均为空 | 允许提交，不触发权重合计校验 |
| 部分目标填写权重 | 不允许提交，提示补齐全部目标权重并保证合计 100% |
| 全部目标填写权重且合计为 100% | 允许提交 |
| 全部目标填写权重但合计不为 100% | 不允许提交，提示调整权重 |

提示文案：

- 权重说明：`可选；如填写权重，各目标权重合计需为 100%。`

### 3.15 [19] 通知与待办

![试用期转正通知与待办流转图](图示/试用期转正通知与待办流转图.svg)

#### 1. 基础逻辑

- 系统需区分“待办”和“待审批”两类事项：待办用于目标设定、目标确认、自评、上级评价、开启评价、发起审批等业务动作；待审批用于转正审批人处理审批单。
- 待办通过邮件 + WOA 发送提醒，WOA 消息需特别注明“仅限 PC 端打开”，并在 OA 消息中心显示待办。
- 待审批通过邮件 + OTP 通知，在 OTP 待处理和 OA 消息中心均提示。
- 除审批外的其他待办本期暂不支持移动端处理。
- 通知 Demo 应表达为“待办与通知预览”，不以“邮件通知场景”为主。
- 通知 Demo 右侧预览应模拟 Outlook 查看邮件的容器效果，让用户感知是在邮件客户端中查看系统通知。
- 通知 Demo 不展示“复制邮件内容”和“显示配置”两个内部辅助按钮。
- 通知 Demo 需要覆盖“转正审批流程”阶段相关通知，包括审批待办、审批完成/驳回通知和身份变更后的结果自动发布通知；不再展示 HRBP 发布结果相关通知。

#### 2. 通知场景

| 场景 | 触发条件 | 接收人 | 形式 | 系统动作 |
| --- | --- | --- | --- | --- |
| 目标设定待办 | 员工入职后即具备权限，入职满 1 周后推送提醒 | 员工 | 待办 + 通知 | 填写并提交目标 |
| 目标退回待办 | 上级退回目标 | 员工 | 待办 + 通知 | 修改并重新提交 |
| 目标确认待办 | 员工提交目标 | 直属上级 | 实时待办 + 通知 | 确认目标或退回修改 |
| 3 个月目标跟进提醒 | 入职满 3 个月且仍处于目标设定/确认阶段 | 直属上级、HRBP | 通知 | 上级确认目标或跟进员工提交；HRBP 跟进整体进度 |
| 目标提交通知 | 员工提交试用期目标 | 直属上级、HRBP | 实时通知 | 上级确认目标；HRBP 跟进后续确认进度 |
| 开启评价待办 | 入职满 4.5 个月且目标已确认 | HRBP | 待办 + 通知 | 开启评价或终止转正 |
| 员工自评待办 | HRBP 开启评价 | 员工 | 待办 + 通知 | 提交试用期评价 |
| 自评进行通知 | HRBP 开启评价 | 直属上级 | 通知 | 知晓员工正在自评，等待后续评价待办 |
| 上级评价待办 | 员工提交自评 | 直属上级 | 待办 + 通知 | 给出试用期评价 |
| 评估跟进通知 | 员工提交自评 | HRBP | 通知 | 跟进上级评价进度 |
| 上级评价不通过通知 | 上级提交“不通过”试用期评价 | HRBP | 通知 | 知晓该员工已进入终止转正状态，并跟进后续人事处理 |
| 上级评价通过通知 | 上级提交通过类试用期评价 | HRBP | 待办 + 通知 | 发起转正 |
| 5.5 个月评估推进提醒 | 入职满 5.5 个月仍未发起转正审批流程 | 直属上级、HRBP | 通知/待办提醒 | HRBP 推动发起转正；如自评或上级评价尚未完成，则同步推动前序环节完成 |
| 5.5 个月未发起审批升级通知 | 入职满 5.5 个月仍未发起转正审批流程 | 员工对应 HRD、HRBP head | 通知 | 知晓转正审批发起延迟，并推动 HRBP 完成后续处理 |
| 发起转正待办 | 上级提交通过类试用期评价 | HRBP | 待办 + 通知 | 发起转正 |
| 审批待办 | HRBP 发起转正审批流程 | 审批人 | 待审批 | 查看审批单并审批 |
| 审批完成通知 | 转正审批通过 | HRBP、直属上级 | 通知 | 知晓审批已完成，等待员工身份变更后系统自动发布结果 |
| 审批驳回通知 | 转正审批被驳回 | HRBP、直属上级 | 通知 | 知晓审批被驳回；HRBP 判断是否重新发起或回退处理 |
| 结果自动发布通知 | 员工身份由试用员工变更为正式员工，系统自动发布结果 | 员工 | 通知 | 员工知晓试用期已通过并查看详情 |

#### 3. 展示边界

- 不展示 3 个月中期 Review。
- 不展示 HRBP 正式评价待办。
- 员工端在目标已确认后、评估开启前不展示单独的“待开启试用期评价”状态。
- WOA 待办消息需注明“仅限 PC 端打开”，避免员工或上级误以为可在移动端完成非审批待办。
- 待审批可在移动端处理，需在 OTP 待处理和 OA 消息中心同时提示。
- 通知 Demo 只展示对业务评审有帮助的待办与通知场景，不展示复制、配置等内部调试能力。

| 目标权重全部为空 | 允许提交，不触发权重合计校验 |
| 目标权重部分填写 | 不允许提交，需补齐全部目标权重并保证合计 100% |
| 目标权重合计不为 100% | 不允许提交，提示调整权重 |
| 上级已确认但评估未开启 | 上级仍可退回目标，员工重新调整 |
| 阶段性反馈无目标 | 弹窗目标区域展示“暂未完成试用期目标制定” |
| 阶段性反馈记录为空 | 员工侧展示“暂无阶段性反馈记录” |
| HRBP 尝试新增阶段性反馈 | 本期不提供入口，HRBP 仅可查看直属上级提交的阶段性反馈 |
| 正式评估已开启 | 上级不再允许新增阶段性反馈，仅可查看历史记录 |
| 到 4.5 个月目标仍未确认 | 是否自动确认待业务确认；建议先不自动确认，改为 HRBP 风险可见并推动处理 |
| HRBP 终止转正 | 单据进入终止转正状态，并保留跳转相关人事流程入口 |
| HRBP 终止转正后发起离职 | 终止转正后的员工展示“发起离职”操作；正式系统跳转离职系统，Demo 不实现跳转 |
| 员工未完成转正流程前离职 | 系统自动作废所有未完成表单，将人员放入“已结束”，状态显示“未转正离职” |
| 员工未完成自评 | 自评待办持续存在；5.5 个月可触发推进提醒 |
| 上级未完成评价 | 上级评价待办持续存在；5.5 个月可触发推进提醒 |
| 入职满 5.5 个月仍未发起审批 | 触发推进提醒；HRBP 负责发起转正，如前序自评或上级评价未完成，则同步推动完成；同时通知员工对应 HRD 和 HRBP head |
| 上级评价不通过 | 记录进入终止转正状态，并通知 HRBP 跟进后续人事处理 |
| 审批退回/拒绝 | 默认回到 HRBP“上级已评价”状态；如审批系统已有回退规则，以审批系统配置为准 |
| 无 HRD 或审批节点缺失 | 按现有审批配置处理，可能由 HRBP 自审批或节点跳过 |
| 审批通过后身份未变更 | 记录进入“待身份变更”，系统等待员工身份从试用员工变更为正式员工 |
| 员工身份变更为正式员工 | 系统自动发布转正结果，员工默认可查看上级评价结果 |

### 7.2 验收标准

流程验收：

- 员工可新增 1-5 条目标并提交。
- 员工目标不再填写目标维度，目标列表第一列展示系统生成的“序号”。
- 员工目标中的“目标内容”和“预期结果”为必填，并在页面列名中展示必填标识。
- 员工可不填写目标权重并提交。
- 员工填写任一目标权重时，需要全部目标填写权重且合计为 100% 后才能提交。
- 上级可确认目标，也可通过二次确认弹窗填写退回意见后退回目标。
- 目标确认表单内不展示退回意见输入组件，退回意见仅在退回二次确认弹窗中填写。
- 上级在 HRBP 开启评价前可退回已确认目标。
- 直属上级在正式转正评估发起前可填写阶段性反馈，HRBP 不可填写阶段性反馈。
- 阶段性反馈不改变主流程状态，不阻断后续转正评估发起。
- 员工可查看阶段性反馈记录，不能编辑、删除、确认或反馈。
- HRBP 点击“开启评价”前需要轻量确认；确认文案为“确认后将通知该员工开始填写试用期自评。”
- HRBP 执行“终止转正”时，确认文案统一为“该员工将进入「终止转正」状态，不再继续转正流程。”
- 员工提交自评后，上级可填写评价和转正建议。
- 上级评价结论选项展示为“通过（超出预期）”“通过（符合预期）”“不通过”。
- 上级评价意见为必填项，无论选择通过或不通过均需填写。
- 上级提交通过类试用期评价后，HRBP 可通过“发起转正”查看审批单预览，并点击“发起转正审批流程”提交。
- 上级提交“不通过”试用期评价后，记录直接进入“终止转正”状态。
- 上级目标确认弹窗不展示“目标回顾”列。
- 审批通过后不再出现 HRBP 发布结果入口；员工身份变更为正式员工后，系统自动发布结果。
- 审批详情展示目标、员工自评、上级评价、阶段性反馈和审批记录。
- 审批详情不展示 HRBP 正式评价。

页面验收：

- 上级端不展示“待处理”Tab，仅展示“未转正”和“已结束”Tab。
- HRBP 端不展示“待处理”Tab，仅展示“未转正”和“已结束”Tab。
- 上级端和 HRBP 端在“未转正”Tab 内提供“待我处理”筛选项。
- 员工首页当前状态模块命名为“当前进展”。
- 员工首页入职天数展示为“已入职 XXX 天”，不展示“共 180 天”。
- 员工切换组件放在侧边栏，不占用员工首页主体内容区。
- Demo 员工切换列表中不再展示“赵雪梅”演示员工。
- 员工当前状态展示在页面标题下方。
- 员工信息和当前进展为上下结构，员工信息在上；员工信息区域桌面端每行展示 3 个字段。
- 员工端在目标已确认到 HRBP 开启评价前，阶段保持“上级确认”，状态展示“【进行中】目标已确认”。
